## Сравнение warm с чистой декомпозицией

По 400 парным запускам warm лучше в 11, равен в 383, хуже в 6; несравнимых — 0. Сравнивается лексикографическая цель. Warm не гарантирует превосходство над чистой декомпозицией: гарантируется только план не хуже baseline. Эти режимы могут использовать разные множества кандидатов; исходы по каждой группе в `warm-vs-decomposition.csv`.

## Ограничение конструкции семейств

В новых конфигах два 30-минутных слота вмещают только отправления в 07:30 и 08:00. Для narrow_r150 независимо проверенная доля заявок, окна которых содержат хотя бы одну из этих минут, по 20 seed в среднем 35,513% (минимум 27,679%, максимум 41,071%); это совпадает со средней долей назначений baseline. Следовательно при высоком R narrow-семейство ограничено несовпадением окон и слотов, а не только общей вместимостью; R не гарантирует достижимость спроса. Для wide_r150 эта доля совместимых окон равна 100% для всех 20 seed, а baseline назначает в среднем 99,978%; оно помечено как контроль без запаса. Это свойство конкретных PLACEHOLDER-конфигов и повод пересмотреть разнообразие слотов до следующих экспериментов.

Расписание выполнения: пять narrow-семейств взяты из первых 600 последовательно записанных запусков; для пяти wide-семейств использованы заранее заданные отдельные процессы (`stage25_parallel_wide.json`). Дополнительная чистая декомпозиция и масштаб частично выполнялись параллельно. Выбор данных производился по имени семейства, seed и режиму, а не по результатам.
